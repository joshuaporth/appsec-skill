## Finding 1: XML External Entity (XXE) Injection

**Finding ID:** `APPSEC-3f8a1c29e7`
**File:** `src/main/java/com/example/demo/main.java`
**Lines:** 36–43
**CWE:** CWE-611 — Improper Restriction of XML External Entity Reference
**OWASP Category:** A05:2021 – Security Misconfiguration
**Priority:** P1
**Severity:** CRITICAL
**Confidence:** HIGH

### Vulnerable Code
```java
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
DocumentBuilder builder = dbf.newDocumentBuilder();
Document doc = builder.parse(new InputSource(new StringReader(inputXml)));

return xmlToString(doc);
```

### Description
`DocumentBuilderFactory.newInstance()` with no hardening flags enables external entity processing by default in Java. The `inputXml` parameter is fully attacker-controlled (unauthenticated `POST /process`), and the parsed `Document` is serialized back to the caller via `xmlToString(doc)`. An attacker can craft a payload with a `SYSTEM` entity pointing to any local file (e.g., `file:///etc/passwd`) or an internal URL; the parser fetches the resource and the serializer echoes its content back in the HTTP response. This yields arbitrary local file read and potentially blind SSRF against internal services.

**Concrete attack payload:**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<foo>&xxe;</foo>
```
POSTed as `inputXml=<above>` to `/process` — the response body will contain `/etc/passwd` contents.

### Prioritization
Highest priority. No preconditions — unauthenticated HTTP POST to a public endpoint, full out-of-band file read in one request. All other findings are lower severity.

### Exploitability Notes
- **Exploit Preconditions:** Network access to the service (port 8081 by default). No authentication required.
- **Uncertainty Boundary:** Java 17+ JDK-bundled parser behavior is consistent with XXE being enabled by default unless feature flags are set. Impact is confirmed regardless of JDK minor version. The only runtime variable is filesystem permissions — some sensitive paths may be unreadable if the process lacks access.

### Remediation
Disable DTD/doctype processing entirely before parsing. The safest approach in Java is:

```java
@RequestMapping(method=RequestMethod.POST, value="/process")
public String process(String inputXml) {
    if (inputXml == null) {
        return "Provide an inputXml variable";
    }

    try {
        DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
        // Disable DOCTYPE declarations entirely — most secure
        dbf.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
        // Belt-and-suspenders: disable external entities explicitly
        dbf.setFeature("http://xml.org/sax/features/external-general-entities", false);
        dbf.setFeature("http://xml.org/sax/features/external-parameter-entities", false);
        dbf.setFeature("http://apache.org/xml/features/nonvalidating/load-external-dtd", false);
        dbf.setXIncludeAware(false);
        dbf.setExpandEntityReferences(false);

        DocumentBuilder builder = dbf.newDocumentBuilder();
        Document doc = builder.parse(new InputSource(new StringReader(inputXml)));
        return xmlToString(doc);
    } catch (Exception e) {
        // Do NOT return e.getMessage() — return a generic error
        return "XML processing error";
    }
}
```

Why: `disallow-doctype-decl` causes the parser to throw on any `<!DOCTYPE` declaration, eliminating both classic XXE and DOCTYPE-based DoS. The additional flags are defense-in-depth for parsers that don't honor the first flag.

## Finding 2: Exception Message Returned to Client (Information Disclosure)

**Finding ID:** `APPSEC-9b2d4e1a05`
**File:** `src/main/java/com/example/demo/main.java`
**Lines:** 41–44
**CWE:** CWE-209 — Generation of Error Message Containing Sensitive Information
**OWASP Category:** A09:2021 – Security Logging and Monitoring Failures
**Priority:** P2
**Severity:** LOW
**Confidence:** HIGH

### Vulnerable Code
```java
} catch (Exception e) {
    e.printStackTrace();
    return e.getMessage();
}
```

### Description
The raw exception message is returned directly in the HTTP response body. During XXE exploitation attempts, `e.getMessage()` may include local filesystem paths, internal hostname details, or network error strings that give an attacker reconnaissance information. Even after XXE is fixed, parse errors for malformed XML will echo internal JVM/library state to the caller. `e.printStackTrace()` writes the full stack trace to server stderr/logs, but the `return e.getMessage()` line makes partial diagnostic information externally observable.

### Prioritization
P2, lower priority than the XXE finding. This issue's primary risk is reconnaissance; it amplifies attacker capability but does not introduce direct data exfiltration on its own.

### Exploitability Notes
- **Exploit Preconditions:** Ability to trigger a parse exception (e.g., send malformed XML or an entity that causes an `IOException`).
- **Uncertainty Boundary:** The exact content of `getMessage()` varies by JDK version and exception type; some messages are generic, others include paths.

### Remediation
Return a generic error string; log the detail server-side only:

```java
} catch (Exception e) {
    // Log full detail for ops, expose nothing to caller
    log.error("XML processing failed", e);
    return "XML processing error";
}
```

Add a `private static final Logger log = LoggerFactory.getLogger(main.class);` field and import `org.slf4j.Logger` / `org.slf4j.LoggerFactory` (included transitively by `spring-boot-starter-web`).

- https://cwe.mitre.org/data/definitions/209.html

## Finding 3: Container Runs as Root

**Finding ID:** `APPSEC-c5f0a8b312`
**File:** `Dockerfile`
**Lines:** 1–9
**CWE:** CWE-250 — Execution with Unnecessary Privileges
**OWASP Category:** A05:2021 – Security Misconfiguration
**Priority:** P3
**Severity:** INFO
**Confidence:** HIGH

### Vulnerable Code
```dockerfile
FROM eclipse-temurin:17-jdk

WORKDIR /app
COPY . .
RUN apt-get update && apt-get install -y maven && mvn clean package -DskipTests
CMD ["java", "-jar", "target/demo-0.0.1-SNAPSHOT.jar"]
```

### Description
No `USER` directive is present, so the JVM process runs as `root` (UID 0) inside the container. Given Finding 1 (XXE local file read), an attacker who reads files as root has access to all filesystem content, not just files owned by a restricted user. Additionally, the image installs the full JDK and Maven toolchain at runtime rather than using a multi-stage build, leaving unnecessary build tools in the final image. The `COPY . .` instruction may inadvertently include `.env` files, IDE configs, or credentials present in the build context.

### Prioritization
P3. No standalone exploitability — this amplifies the impact of Finding 1 but doesn't constitute an independent vulnerability without a code-level exploit path.

### Exploitability Notes
- **Exploit Preconditions:** Requires another vulnerability (e.g., XXE) to leverage the root privilege.
- **Uncertainty Boundary:** Container runtime configuration (e.g., `--read-only` rootfs, seccomp profiles, AppArmor) could partially mitigate; not visible from this scope.

### Remediation
```dockerfile
# Stage 1: build
FROM eclipse-temurin:17-jdk AS builder
WORKDIR /app
COPY . .
RUN apt-get update && apt-get install -y maven && mvn clean package -DskipTests

# Stage 2: minimal runtime image, non-root user
FROM eclipse-temurin:17-jre
RUN groupadd -r appuser && useradd -r -g appuser appuser
WORKDIR /app
COPY --from=builder /app/target/demo-0.0.1-SNAPSHOT.jar app.jar
USER appuser
CMD ["java", "-jar", "app.jar"]
```

Why: multi-stage build strips Maven and JDK from the final image; `USER appuser` ensures the JVM process runs without root privileges.
