## Finding 1: Unrestricted Reflection / Class Loading — Immediate Privilege Escalation

**Finding ID:** `APPSEC-ctrl470-cfa3b8d291`  
*(Constructed from: `src/main/java/com/example/demoapp/Controller.java` + `CWE-470` + `Class.forName(user)`)*  
**File:** `src/main/java/com/example/demoapp/Controller.java`  
**Lines:** 17–22  
**CWE:** CWE-470 — Use of Externally-Controlled Input to Select Classes or Code  
**OWASP Category:** A01:2021 – Broken Access Control; A03:2021 – Injection  
**Priority:** P1  
**Severity:** CRITICAL  
**Confidence:** HIGH

### Vulnerable Code
```java
Class<?> clazz = Class.forName(user);
Method method = clazz.getMethod("sayHello");
Object instance = clazz.getDeclaredConstructor().newInstance();
Object result = method.invoke(instance);
```

### Description
The `user` query parameter is passed without any validation directly to `Class.forName()`, which loads and initializes any class on the JVM classpath. The code then reflectively instantiates that class and invokes its `sayHello()` method. An unauthenticated attacker can immediately escalate privileges to the `AdminUser` role by issuing:

```
GET /custom-hello?user=com.example.demoapp.AdminUser
→ HTTP 200 "Hello! You're an admin!"
```

Beyond the direct privilege bypass, `Class.forName()` runs **static initializers** on any class it loads. In a Spring Boot fat JAR the classpath contains hundreds of third-party classes; if any such class carries a dangerous static initializer, loading it can cause unintended side effects. The attack surface grows proportionally with classpath complexity.

### Prioritization
Top priority. This is a zero-precondition, unauthenticated, one-request exploit. There is no higher-priority finding in this codebase.

### Exploitability Notes
- **Exploit Preconditions:** None. Any anonymous HTTP client can reach `GET /custom-hello`. The target class must be on the classpath (confirmed: `AdminUser` is).
- **Uncertainty Boundary:** RCE via static initializer gadgets depends on what's on the runtime classpath; confirmed impact is privilege escalation. A reverse proxy or API gateway sitting in front that blocks the endpoint would change impact.

**Counterfactual invalidation:** Replacing the reflection lookup with a strict allow-listed `switch`/`if` on a known enum of role names would eliminate this finding entirely.

### Remediation
Remove the reflection-based dispatch entirely. Route to known types using an explicit map or switch:

```java
@GetMapping("/custom-hello")
public String customHello(@RequestParam String user) {
    return switch (user) {
        case "normal" -> new NormalUser().sayHello();
        // Do NOT include admin here — require authentication + authorization instead.
        default -> "Unknown user type.";
    };
}
```

If dynamic dispatch is genuinely required by a future design, enforce both an **explicit allowlist** and **authentication + role check** before allowing any class outside the `NormalUser` category:

```java
private static final Set<String> ALLOWED_CLASSES = Set.of(
    "com.example.demoapp.NormalUser"
);

@GetMapping("/custom-hello")
public String customHello(@RequestParam String user) {
    if (!ALLOWED_CLASSES.contains(user)) {
        return ResponseEntity.status(HttpStatus.FORBIDDEN).body("Denied");
    }
    // ... reflection limited to explicitly allowed classes
}
```

## Finding 2: Information Disclosure via Exception Message

**Finding ID:** `APPSEC-ctrl209-b3e17fa852`  
*(Constructed from: `src/main/java/com/example/demoapp/Controller.java` + `CWE-209` + `"Error invoking method: " + e.getMessage()`)*  
**File:** `src/main/java/com/example/demoapp/Controller.java`  
**Lines:** 24–25  
**CWE:** CWE-209 — Generation of Error Message Containing Sensitive Information  
**OWASP Category:** A04:2021 – Insecure Design  
**Priority:** P3  
**Severity:** LOW  
**Confidence:** HIGH

### Vulnerable Code
```java
} catch (Exception e) {
    return "Error invoking method: " + e.getMessage();
}
```

### Description
`e.getMessage()` for reflection exceptions (`ClassNotFoundException`, `NoSuchMethodException`, `InstantiationException`) leaks internal JVM classpath structure to the caller. An attacker can enumerate which class names are valid on the classpath by probing responses — aiding reconnaissance before a targeted reflection or deserialization attack. For example, `ClassNotFoundException: com.example.SomeClass` confirms the class does not exist; silence or a different error confirms it does.

### Prioritization
P3 — secondary to Finding 1. Fix Finding 1 first; if the endpoint is removed or properly gated, this disclosure path disappears with it.

### Exploitability Notes
- **Exploit Preconditions:** Attacker must be able to reach the `/custom-hello` endpoint (no auth currently).
- **Uncertainty Boundary:** A WAF or reverse proxy that strips response bodies with exception strings would reduce exposure.

### Remediation
```java
} catch (Exception e) {
    // Log internally, return a generic message to the caller.
    log.error("customHello dispatch error for user={}", user, e);
    return "Invalid request.";
}
```

- https://cwe.mitre.org/data/definitions/209.html

## Finding 3: No Authentication on Any Endpoint

**Finding ID:** `APPSEC-ctrl306-9d4c2ea71f`  
*(Constructed from: `src/main/java/com/example/demoapp/Controller.java` + `CWE-306` + `no Spring Security configuration`)*  
**File:** `src/main/java/com/example/demoapp/Controller.java`; `src/main/java/com/example/demoapp/DemoApplication.java`  
**Lines:** 9–27 (Controller); entire application  
**CWE:** CWE-306 — Missing Authentication for Critical Function  
**OWASP Category:** A07:2021 – Identification and Authentication Failures  
**Priority:** P3  
**Severity:** INFO  
**Confidence:** MEDIUM

### Vulnerable Code
```java
@RestController
public class Controller {
    @GetMapping("/hello")           // no @PreAuthorize, no SecurityConfig
    public String hello() { ... }

    @GetMapping("/custom-hello")    // no @PreAuthorize, no SecurityConfig
    public String customHello(@RequestParam String user) { ... }
}
```

### Description
There is no Spring Security configuration, no filter chain, and no method-level security annotations anywhere in the project. The `/custom-hello` endpoint — which can instantiate privileged classes — is accessible to anonymous callers. Even after fixing the reflection issue (Finding 1), future additions of genuinely privileged operations would ship unauthenticated by default given the current security posture.

### Prioritization
P3 / INFO — on its own this is a structural gap rather than an immediately exploitable path. The exploitable finding is captured in Finding 1, which depends on this authentication absence as a precondition.

### Exploitability Notes
- **Exploit Preconditions:** Depends on what endpoints exist; by itself the absence of auth is not exploitable.
- **Uncertainty Boundary:** An external auth proxy (API gateway, mTLS sidecar) not visible in this scope could enforce authentication before traffic reaches the app. Rated MEDIUM confidence because of this.

### Remediation
Add Spring Security with a minimal secure-by-default configuration and use method-level security for sensitive endpoints:

```xml
<!-- pom.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
```

```java
@Configuration
@EnableMethodSecurity
public class SecurityConfig {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/hello").permitAll()
                .anyRequest().authenticated()
            )
            .httpBasic(Customizer.withDefaults());
        return http.build();
    }
}
```

Then restrict admin-capable routes with `@PreAuthorize("hasRole('ADMIN')")`.

- https://docs.spring.io/spring-security/reference/
