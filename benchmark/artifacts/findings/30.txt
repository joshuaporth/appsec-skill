## Finding 1: Server-Side Request Forgery / Local File Inclusion via wkhtmltopdf

**Finding ID:** `APPSEC-a3f82c1d4e`
**File:** `main.go`
**Lines:** 24–36
**CWE:** CWE-918 — Server-Side Request Forgery (also covers CWE-73 LFI)
**OWASP Category:** A10:2021 – Server-Side Request Forgery
**Priority:** P1
**Severity:** CRITICAL
**Confidence:** HIGH

### Vulnerable Code
```go
html := fmt.Sprintf(`
<html><body>
  <h1>Company Report</h1><hr/>
  %s
  <hr/><footer>Generated by Challenge 30 - PDF API</footer>
</body></html>`, req.Content)

pdfg, _ := wkhtmltopdf.NewPDFGenerator()
pdfg.AddPage(wkhtmltopdf.NewPageReader(bytes.NewReader([]byte(html))))
if err := pdfg.Create(); err != nil {
```

### Description
`req.Content` — raw, unsanitized attacker input — is interpolated directly into an HTML document with `fmt.Sprintf` using `%s` (no HTML escaping), then fed to `wkhtmltopdf`. `wkhtmltopdf` is a headless Qt WebKit browser: it executes JavaScript, follows `<iframe src>`, loads `<img src>`, and honors `file://` URLs by default. An attacker who controls the HTML source can (a) read arbitrary local files by injecting `<iframe src="file:///etc/passwd">` or XHR JavaScript, (b) reach internal HTTP services (AWS/GCP metadata APIs, internal microservices) with `<img src="http://169.254.169.254/latest/...">`, and (c) exfiltrate results out-of-band to an attacker-controlled server — all with no preconditions beyond network access to the `/render` endpoint. The Dockerfile runs the process as root (no `USER` directive), meaning every file on the container filesystem is readable.

### Prioritization
Highest priority. This is an unauthenticated, no-precondition SSRF/LFI with direct data exfiltration capability. Remediation must block both the injection path (HTML sanitization or a content allowlist) and the renderer capabilities (disable JS, disable local file access in wkhtmltopdf).

### Exploitability Notes
- **Exploit Preconditions:** Network access to `POST /render`. No authentication required (see Finding 2). Attacker must control JSON `content` field.
- **Uncertainty Boundary:** The exact files readable depends on container filesystem content. Cloud metadata SSRF depends on whether the container is running in a cloud environment with an IMDS endpoint. JavaScript-based XHR file reads depend on the wkhtmltopdf version installed by apt on Debian Bullseye (0.12.5), which permits local file reads via XHR by default.

**Concrete attack payload — LFI:**
```
POST /render HTTP/1.1
Content-Type: application/json

{"content": "<script>var x=new XMLHttpRequest();x.open('GET','file:///etc/passwd',false);x.send();document.write('<pre>'+x.responseText+'</pre>');</script>"}
```

**Concrete attack payload — SSRF (cloud metadata):**
```json
{"content": "<iframe src='http://169.254.169.254/latest/meta-data/iam/security-credentials/'></iframe>"}
```

**Counterfactual invalidation:** If `req.Content` were HTML-sanitized (stripping all tags except a safe subset, with no URL schemes other than `https://` and no JS), AND wkhtmltopdf were invoked with `--disable-local-file-access --no-background --disable-javascript`, this finding would no longer be exploitable.

### Remediation
**Option A (preferred): HTML sanitization + renderer hardening**

Use a Go HTML sanitizer (e.g., `github.com/microcosm-cc/bluemonday`) to strip all dangerous tags and schemes before interpolation, and invoke wkhtmltopdf with hardening flags:

```go
import (
    "github.com/microcosm-cc/bluemonday"
)

func renderHandler(w http.ResponseWriter, r *http.Request) {
    var req Req
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
        http.Error(w, "Invalid JSON", 400)
        return
    }

    // Strict allowlist: only safe formatting tags, no JS, no remote URLs
    policy := bluemonday.StrictPolicy()
    safeContent := policy.Sanitize(req.Content)

    html := fmt.Sprintf(`<html><body>
  <h1>Company Report</h1><hr/>
  %s
  <hr/><footer>Generated by Challenge 30 - PDF API</footer>
</body></html>`, safeContent)

    pdfg, err := wkhtmltopdf.NewPDFGenerator()
    if err != nil {
        http.Error(w, "PDF gen failed", 500)
        return
    }
    page := wkhtmltopdf.NewPageReader(bytes.NewReader([]byte(html)))
    // Harden the renderer
    page.DisableJavascript.Set(true)
    page.NoBackground.Set(true)
    pdfg.AddPage(page)
    // Also add at generator level:
    pdfg.NoOutline.Set(true)
    ...
}
```

Additionally, pass `--disable-local-file-access` to wkhtmltopdf at invocation time (library config or wrapper args).

**Option B (defence-in-depth): network-isolate the container** — run the PDF container with no outbound internet access, blocking metadata IP `169.254.169.254` at the network layer. This does not fix LFI but limits SSRF blast radius.

- [CWE-918: Server-Side Request Forgery](https://cwe.mitre.org/data/definitions/918.html)
- [wkhtmltopdf SSRF/LFI known attack class](https://www.virtuesecurity.com/kb/wkhtmltopdf-file-inclusion-vulnerability-2/)

## Finding 2: Missing Authentication on PDF Render Endpoint

**Finding ID:** `APPSEC-b7c943e210`
**File:** `main.go`
**Lines:** 17–40, 43
**CWE:** CWE-306 — Missing Authentication for Critical Function
**OWASP Category:** A07:2021 – Identification and Authentication Failures
**Priority:** P1
**Severity:** HIGH
**Confidence:** HIGH

### Vulnerable Code
```go
func main() {
    http.HandleFunc("/render", renderHandler)
    fmt.Println("Listening on http://localhost:5000")
    log.Fatal(http.ListenAndServe(":5000", nil))
}
```

### Description
The `/render` endpoint performs PDF generation (a computationally expensive operation with significant SSRF/LFI capabilities) without any authentication check. There is no API key validation, session check, bearer token verification, or IP allowlist. Any internet-reachable client can call `POST /render` and exploit the full attack surface described in Finding 1. This compounds Finding 1: authentication would have been a meaningful control limiting SSRF/LFI exploitation to authorized callers.

### Prioritization
P1 alongside Finding 1 — authentication is the first defense that could prevent Finding 1 from being exploited by arbitrary internet actors. Address both together.

### Exploitability Notes
- **Exploit Preconditions:** Network reachability to port 5000. `docker-compose.yml` maps `5000:5000` publicly.
- **Uncertainty Boundary:** If the service is deployed behind an authenticating reverse proxy or VPN not shown in scope, risk is partially mitigated. No such proxy is evidenced in the provided files.

### Remediation
Add API key middleware before the handler:

```go
func apiKeyMiddleware(next http.HandlerFunc) http.HandlerFunc {
    apiKey := os.Getenv("API_KEY")
    if apiKey == "" {
        log.Fatal("API_KEY environment variable must be set")
    }
    return func(w http.ResponseWriter, r *http.Request) {
        provided := r.Header.Get("X-API-Key")
        if !hmac.Equal([]byte(provided), []byte(apiKey)) {
            http.Error(w, "Unauthorized", http.StatusUnauthorized)
            return
        }
        next(w, r)
    }
}

func main() {
    http.HandleFunc("/render", apiKeyMiddleware(renderHandler))
    log.Fatal(http.ListenAndServe(":5000", nil))
}
```

Use `hmac.Equal` (constant-time) rather than `==` for the key comparison to prevent timing oracle attacks on the key. Set `API_KEY` via environment variable in `docker-compose.yml` (not hardcoded in source).

### References
- [CWE-306: Missing Authentication for Critical Function](https://cwe.mitre.org/data/definitions/306.html)
- [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)

## Finding 3: Container Process Runs as Root

**Finding ID:** `APPSEC-c1d456f789`
**File:** `Dockerfile`
**Lines:** 11–22
**CWE:** CWE-250 — Execution with Unnecessary Privileges
**OWASP Category:** A05:2021 – Security Misconfiguration
**Priority:** P2
**Severity:** MEDIUM
**Confidence:** HIGH

### Vulnerable Code
```dockerfile
FROM debian:bullseye

RUN apt-get update && apt-get install -y \
    wkhtmltopdf \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY --from=builder /app/app .

EXPOSE 5000
CMD ["./app"]
```

### Description
No `USER` directive is present in the runtime stage, so the application and `wkhtmltopdf` process run as UID 0 (root) inside the container. Combined with Finding 1, this means that LFI via wkhtmltopdf can read any file on the container filesystem — `/etc/shadow`, mounted secrets, environment variable files, and any credentials injected at runtime. If a container escape vulnerability exists in the kernel or runtime, root inside the container maps to root on the host. The impact of Finding 1 is materially elevated by this misconfiguration.

### Prioritization
P2 — secondary to Findings 1 and 2 because it amplifies rather than introduces the primary risk. Remediate alongside Finding 1.

### Exploitability Notes
- **Exploit Preconditions:** Exploitation requires Finding 1 (SSRF/LFI) to be exploitable to gain practical advantage from root execution. Independently, root-in-container increases container escape risk.
- **Uncertainty Boundary:** Impact depends on what secrets/volumes are mounted into the container at runtime.

### Remediation
Add a non-root user to the Dockerfile runtime stage:

```dockerfile
FROM debian:bullseye

RUN apt-get update && apt-get install -y \
    wkhtmltopdf \
    && rm -rf /var/lib/apt/lists/* \
    && groupadd -r appuser && useradd -r -g appuser appuser

WORKDIR /app
COPY --from=builder /app/app .
RUN chown appuser:appuser /app/app

USER appuser
EXPOSE 5000
CMD ["./app"]
```

### References
- [CWE-250: Execution with Unnecessary Privileges](https://cwe.mitre.org/data/definitions/250.html)
- [Docker Security Best Practices — Non-root user](https://docs.docker.com/develop/security-best-practices/)

## Finding 4: Ignored Error Return from PDF Generator Initialization

**Finding ID:** `APPSEC-d2e567a891`
**File:** `main.go`
**Line:** 31
**CWE:** CWE-252 — Unchecked Return Value
**OWASP Category:** A05:2021 – Security Misconfiguration
**Priority:** P3
**Severity:** LOW
**Confidence:** HIGH

### Vulnerable Code
```go
pdfg, _ := wkhtmltopdf.NewPDFGenerator()
pdfg.AddPage(wkhtmltopdf.NewPageReader(bytes.NewReader([]byte(html))))
```

### Description
The error return from `wkhtmltopdf.NewPDFGenerator()` is silently discarded with `_`. If initialization fails (e.g., the `wkhtmltopdf` binary is missing or not executable), `pdfg` is `nil` and the immediately following `pdfg.AddPage(...)` call panics with a nil pointer dereference. Go's `net/http` server recovers from panics in handlers (since Go 1.8) and returns a 500, but the response body is empty — the caller receives no useful diagnostic and the failure mode is invisible in logs. An attacker observing 500 vs. 400 response shapes gains limited information, but this primarily impacts availability and observability.

### Prioritization
P3 — no direct security exploitation path independent of other findings. Fix alongside any other changes to `renderHandler`.

### Exploitability Notes
- **Exploit Preconditions:** `wkhtmltopdf` binary absent or not executable at runtime.
- **Uncertainty Boundary:** If the binary is always present (guaranteed by the Dockerfile), this panic path is unreachable in normal operation.

### Remediation
```go
pdfg, err := wkhtmltopdf.NewPDFGenerator()
if err != nil {
    log.Printf("wkhtmltopdf init error: %v", err)
    http.Error(w, "PDF gen failed", 500)
    return
}
```

### References
- [CWE-252: Unchecked Return Value](https://cwe.mitre.org/data/definitions/252.html)
